# retype

<img src="assets/retype.png" alt="retype icon" width="96" align="right">

Fix text typed in the wrong keyboard layout with one key: `ghbdtn` → `привет`,
`руддщ` → `hello`. A small Windows tray utility in the spirit of Punto
Switcher, with hard privacy guarantees:

- no network access of any kind: no updates, no telemetry, no "cloud";
- typed text stays in memory, is never logged and never written to disk;
- one small native `.exe` (~0.5 MB), no installer, no runtime.

## Features

- **Convert the last word** (`Pause`, or tap right Shift twice) or the **last
  line** (`Shift+Pause`): retype erases it and types the same keys again in
  the other layout. Press again to convert back.
- **Convert the selection** (`Scroll Lock`), via the clipboard, which is
  restored afterwards.
- **Layout indicator** in the tray: `EN` / `RU` / … on a colored square, grey
  while paused.
- Any set of installed layouts; two layouts toggle, more follow `mode`
  (`pair` or `cycle`).
- **Excluded apps** (e.g. password managers): nothing is recorded there.
- **Autoswitch** (optional, off by default): words typed in the wrong
  layout are fixed after Space, using built-in letter statistics for
  English, Russian and Ukrainian. Press the convert-word hotkey right after
  a correction to undo it.
- Pause/resume (`Ctrl+Pause` or the tray), optional start with Windows,
  config reloaded when the file changes.

## Install

1. Download `retype.exe` and `retype.exe.sha256` from
   [Releases](https://github.com/5avel/Retype/releases).
2. Check the hash in PowerShell; it must match the one in the `.sha256` file:

   ```powershell
   (Get-FileHash retype.exe -Algorithm SHA256).Hash
   ```

3. Put `retype.exe` anywhere and run it. To start it with Windows, use
   "Start with Windows" in the tray menu.

The exe is not code-signed, so SmartScreen may warn on first start. If you
prefer not to trust a binary, build it yourself (below).

Requirements: Windows 10 1809+ or Windows 11, x64.

## Build from source

Requirements: [Rust](https://rustup.rs) stable with the MSVC toolchain
(Visual Studio Build Tools, "Desktop development with C++").

```powershell
git clone https://github.com/5avel/Retype.git
cd Retype
cargo build --release -p retype
```

The binary is `target\release\retype.exe`. Checks used in CI:

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

The core logic (`crates/retype-core`) builds and tests on any OS; the app
crate does real work only on Windows. Dependencies: `windows`, `log`,
`serde`, `toml` (see `docs/DECISIONS.md`, ADR-005). The app icon is
generated by `tools/make_icon.py`, the autoswitch letter tables by
`tools/make_ngrams.py` (both standard library only; the tables are built
from public-domain texts that are not part of the repository).

## Configuration

Tray → "Open config" creates `%APPDATA%\retype\config.toml` from
[`config.example.toml`](config.example.toml) and opens it. Saved changes are
applied within a couple of seconds; a broken file is reported in the log
and the previous settings stay. Portable mode: put an empty file named
`portable` next to the exe to keep the config there.

| Action                   | Default key        |
|--------------------------|--------------------|
| Convert last word        | `Pause`            |
| Convert last word (alt.) | Double right Shift |
| Convert last line        | `Shift+Pause`      |
| Convert selection        | `Scroll Lock`      |
| Pause / resume           | `Ctrl+Pause`       |

Log: `%LOCALAPPDATA%\retype\retype.log` (event kinds and counts only).

## Privacy

- No networking code and no network crates, enforced in CI by `deny.toml`
  and `crates/retype/tests/policy.rs`.
- Keystrokes are kept as key codes (not characters) in a bounded in-memory
  buffer of one line (at most 512 keys), cleared on Enter, mouse click,
  focus change, Ctrl/Alt/Win shortcuts and after 30 s idle, and overwritten
  before release.
- The log never contains typed text, key codes or the names of the apps you
  use.
- No code is injected into other processes: only low-level hooks.
- Text retype puts on the clipboard is marked to stay out of the Windows
  clipboard history and cloud sync.
- Autoswitch remembers words you undid only as hashes, at most 128, in
  memory, until retype exits.

## Known limitations

- Windows of apps running as administrator are not affected while retype
  runs without elevation (Windows UIPI); this is by design.
- Selection conversion uses the app's own copy (Ctrl+Insert), so the
  selected text can appear in the Win+V clipboard history. If an app takes
  longer than ~0.8 s to copy, the clipboard may not be restored.
- In VS Code, with nothing selected, copy takes the whole line, so the whole
  line is converted.
- Consoles report layouts unreliably; there a conversion may leave the text
  unchanged.
- Two variants of one language (e.g. US and Dvorak) cannot both be
  configured.
- Double right Shift: Windows offers to turn on Sticky Keys after five Shift
  presses in a row, and retype's own typing does not reset that count, so
  converting several words in a row with double Shift can bring up the
  prompt. Answer "No" and turn off its shortcut in Settings → Accessibility
  → Keyboard → Sticky keys → "Keyboard shortcut for Sticky keys", or use
  `Pause`, or set `double_right_shift = false`.
